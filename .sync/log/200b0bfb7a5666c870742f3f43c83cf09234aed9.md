# Port: feat(module): add `@nuxt/ui/eslint` config

**Upstream:** `200b0bfb7a5666c870742f3f43c83cf09234aed9` (nuxt/ui, #7329)
**Decision:** port (поздний порт; сначала записан как skip в #28, перенос — задача #25)

## Что в апстриме

Новый экспорт `@nuxt/ui/eslint` — конфигурация ESLint на `eslint-plugin-better-tailwindcss` с правилами для классов и цветов Nuxt UI, опция модуля `eslint` (добавляет конфигурацию к той, что генерирует `@nuxt/eslint`), optional peer `eslint-plugin-better-tailwindcss`, две страницы документации.

## История решения

При первой обработке коммит пропущен (`skip`, #28): правила завязаны на палитру Nuxt UI (`primary`, `neutral`, `neutral-*` → `text-default`), а в b24ui действует система токенов air. Перенос с адаптацией вынесен в #25 и сделан позже; запись реестра переведена в `port`, `pr` и `b24ui_sha` остались от первой обработки (пустые значения посреди реестра ломают `sync-ledger.spec.ts`).

В основу взято состояние файлов на `v4` (657697d9), а не сам коммит: после него вышли `a2682bb7` (конфигурация на Windows, дефисы в именах палитр) и `853356f7` (классы собственных палитр). Первое перенесено (файловый URL в `import`, регулярное выражение для `colors`-блока не нужно), второе — нет: собственных палитр и псевдонимов цветов в b24ui нет.

## Что перенесено

- `src/eslint.ts`, `src/utils/eslint.ts`, экспорт `./eslint` и `typesVersions`, запись в `build.config.ts` (entry и externals).
- Опция модуля `eslint` (`src/module.ts`, `defaultOptions.eslint = false`), исключена из `Bitrix24UIOptions` (`src/unplugin.ts`), как `content`.
- Optional peer `eslint-plugin-better-tailwindcss: ^4.10` (в `devDependencies` пакет уже есть через каталог).
- Документация: `docs/content/docs/1.getting-started/6.integrations/8.eslint/` (Nuxt и Vue), раздел `eslint` на странице установки, адреса в `docs/nuxt.config.ts`.

## Что изменено по сравнению с апстримом

| Апстрим | b24ui | Почему |
|---|---|---|
| `NuxtUIESLintOptions`, `nuxtUI()`, конфигурация `nuxt-ui/tailwindcss` | `Bitrix24UIESLintOptions`, `b24ui()`, `b24ui/tailwindcss` | имена пакета и ключа `b24ui` |
| `@nuxt/ui/eslint` | `@bxshefby/b24ui-nuxt/eslint` | имя пакета, PORTING.md §1 |
| `:ui`, `<UTheme :props>` `{ x: { ui } }`, `defineAppConfig({ ui })`, `ui()` плагина Vite | `:b24ui`, `<B24Theme :props>` `{ x: { b24ui } }`, `defineAppConfig({ b24ui })`, `bitrix24UIPluginVite()` | пропс `b24ui`, PORTING.md §1; имя вызова плагина — как в документации |
| опция `colors`, `readAppConfigColors`, псевдонимы `primary`/`error`/… | нет | в b24ui нет `ui.colors` и псевдонимов палитр: цвета компонентов — значения `air-*` пропса `color`, а не классы |
| `neutral` — псевдоним (в списке серых нет) | `neutral` — обычная серая палитра Tailwind | над `--color-neutral-*` в b24ui ничего не стоит |
| токены `text-default/muted/dimmed/toned/highlighted/inverted`, `bg-default/muted/elevated/accented/inverted`, `border-*`/`ring-*`/`divide-*` по таблице оттенков Nuxt UI | токены из `@theme` в `src/runtime/index.css`: `text-dimmed/muted/description/legend/label`, `bg-default/muted/elevated/accented`, `border-default/muted/accented`, `ring-*`/`divide-*` default/muted/accented; оттенки разложены по светлоте токенов в контекстах light и dark | `text-default`, `text-toned`, `text-highlighted`, `text-inverted`, `bg-inverted` в b24ui не объявлены |
| оттенок цвета → псевдоним (`bg-red-500` → `bg-error-500`) | оттенок цвета → фирменный цвет без оттенка (`red` → `alert`, `orange`/`amber`/`yellow` → `warning`, `lime`/`green`/`emerald` → `success`, `sky`/`blue` → `primary`, `indigo`/`violet`/`purple`/`fuchsia` → `ai`) | `--color-*` в `air-design-tokens/tw-style/colors.css`; `teal`, `cyan`, `pink` аналога не имеют — общее сообщение |
| в сообщениях «semantic token or the `neutral` color» | «семантический токен, фирменный цвет или проп `color` компонента» | нет цвета `neutral` |
| `border-accented` не отличается от прочих | серые не сопоставляются `border-accented` | это насыщенный синий акцент, не серая граница |

## Проверка

- `test/utils/eslint-config.spec.ts` — правила на настоящем ESLint (`.vue`, `app.config.ts`, плагин Vite), и каждый токен из подсказок найден в `src/runtime/index.css` или `colors.css`.
- `test/module/module-setup.spec.ts` — опция `eslint` модуля: хук `eslint:config:addons`, точка входа, предупреждения.
- Мутации: недопустимый токен в таблице, убранный `neutral`, чужой селектор, несуществующий цвет, потерянный модификатор непрозрачности, пропущенная проверка своей конфигурации, переименованный хук — каждая краснит свой тест.

## Не сделано

Саму конфигурацию репозиторий на себя не включает: в `docs/` и `playgrounds/` есть классы `bg-gray-950`, `from-red-500` и подобные (демонстрационные), и включение дало бы десятки предупреждений. Решение — за владельцем.

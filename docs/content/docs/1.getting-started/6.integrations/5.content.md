## Установка {#installation}

Начните с официального [руководства](https://content.nuxt.com/docs/getting-started/installation) или с краткого пересказа:

::code-group{sync="pm"}

```bash [pnpm]
pnpm add @nuxt/content
```

```bash [yarn]
yarn add @nuxt/content
```

```bash [npm]
npm install @nuxt/content
```

```bash [bun]
bun add @nuxt/content
```

::

Затем добавьте модуль `@nuxt/content` в `nuxt.config.ts`:

```ts [nuxt.config.ts] {4}
export default defineNuxtConfig({
  modules: [
    '@bitrix24/b24ui-nuxt',
    '@nuxt/content'
  ],
  css: ['~/assets/css/main.css']
})
```

::caution
Регистрируйте `@nuxt/content` в массиве `modules` после `@bitrix24/b24ui-nuxt`, иначе компоненты prose будут недоступны.
::

## Настройка {#configuration}

Если в Markdown-файлах контента используются классы Tailwind CSS, нужно сделать так, чтобы Tailwind смог их обнаружить и сгенерировать нужные утилиты. Автоматическое определение содержимого в Tailwind по умолчанию может не заметить классы, написанные в Markdown-файлах.

Для этого добавьте в CSS-файл [директиву `@source`](https://tailwindcss.com/docs/functions-and-directives#source-directive), которая явно включает каталог с контентом:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@bitrix24/b24ui-nuxt";

@source "../../../content/**/*";
```

Тогда:
- Tailwind сканирует все Markdown-файлы в каталоге контента
- утилитарные классы из вашего Markdown попадают в итоговый CSS
- динамические классы в MDC-компонентах и собственных Vue-компонентах внутри контента работают как надо

::tip
Чтобы точнее указать, какие файлы сканировать, можно использовать glob-шаблоны:
- `@source "../../../content/docs/**/*.md"` — сканировать только Markdown в каталоге docs
- `@source "../../../content/**/*.{md,yml}"` — сканировать Markdown и YAML
::

::note{to="https://tailwindcss.com/docs/detecting-classes-in-source-files" target="_blank"}
Подробнее об автоматическом определении содержимого в Tailwind и о том, как ускорить сборку.
::

## Приложения только для клиента (SPA) {#client-only-apps-spa}

Компоненты prose в приложении только для клиента (`ssr: false`{lang="ts-type"}) работают так же, как при серверной отрисовке: в этом режиме ничего в отрисовке Markdown не отключается. Nuxt Content переносит свою базу данных в браузер: при первом запросе клиент скачивает дамп из `/__nuxt_content/<collection>/sql_dump.txt` и отвечает на все запросы локально через WASM SQLite.

::caution
Дамп содержит **всю коллекцию**, а не только страницы, на которые вы ссылаетесь, и кэшируется в `localStorage`. Всё, что лежит в коллекции, к которой обращается страница с клиентской отрисовкой, может прочитать любой посетитель, поэтому черновики и непубличные документы храните в отдельной коллекции.
::

### Сборке всё равно нужен SQLite {#the-build-still-needs-sqlite}

Дамп создаётся при сборке, поэтому сборке нужен рабочий адаптер SQLite, хотя развёрнутое приложение его не запускает. Именно здесь обычно ломается сборка приложения только для клиента: адаптер по умолчанию `better-sqlite3` — нативный модуль, который компилируется при установке. Без него сборка падает с ошибкой `Could not locate the bindings file`, дамп не создаётся, и контент на страницу не попадает.

В Node.js 22.5 и новее нативную привязку можно не использовать вовсе и взять встроенный в Node модуль `node:sqlite`. Это одна строка, без компилятора и без привязки к менеджеру пакетов:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    experimental: {
      sqliteConnector: 'native'
    }
  }
})
```

Так собран сайт этой документации.

В более старых версиях Node.js `better-sqlite3` приходится компилировать, а pnpm не запускает скрипты установки зависимости, пока вы это не разрешите:

```yaml [pnpm-workspace.yaml]
allowBuilds:
  better-sqlite3: true
```

Команда `pnpm approve-builds` запишет эту строку за вас — это способ, который работает в любой версии: в pnpm 11 прежние настройки `onlyBuiltDependencies` и `ignoredBuiltDependencies` заменены таким списком. Без разрешения установка сразу завершается ошибкой `ERR_PNPM_IGNORED_BUILDS`; в pnpm 10 установка проходит и лишь выводит примечание, поэтому в этой версии проблему легко пропустить. Разрешайте только тот пакет, который нужен, а не `pnpm approve-builds --all` и не `dangerouslyAllowAllBuilds`: скрипт установки выполняет произвольный код на вашем компьютере и в CI, и от этого защищает настройка по умолчанию.

npm и yarn по умолчанию запускают скрипты установки, поэтому сбой `better-sqlite3` у них означает отсутствие инструментов сборки C++, а не заблокированный скрипт: установите их или переключите коннектор, как описано выше.

::note{to="https://content.nuxt.com/docs/getting-started/configuration" target="_blank"}
Полный список коннекторов SQLite — в справочнике по настройке Nuxt Content.
::

### Страница ничего не показывает {#when-a-page-renders-nothing}

Двигайтесь от сборки наружу — на каждом шаге ответ свой:

1. **Есть ли дамп в результате сборки?** После сборки найдите `.output/public/__nuxt_content/<collection>/sql_dump.txt`. Если файла нет, сборка его не создала — причину ищите в адаптере SQLite, описанном выше.
2. **Получает ли его браузер?** На вкладке Network этот файл должен загружаться при первом запросе. Ошибка 404 обычно означает, что сайт отдаётся из подкаталога, который не учтён в `app.baseURL`.
3. **Находит ли запрос что-нибудь?** Эта загрузка выбрасывает исключение, а не возвращает пустой результат, поэтому отсутствие дампа проявляется в `error`, а не в `data`. Пустой `data` без ошибки — другая проблема, обычно фильтр по пути, которому не соответствует ни один документ.

```vue
<script setup lang="ts">
// `content` — имя коллекции по умолчанию; если вы её переименовали, укажите своё
const { data: all, error } = await useAsyncData('all', () => queryCollection('content').all())

// у `content/index.md` путь `/`, а не `/index`
if (import.meta.dev) {
  console.log(error.value, all.value?.length, all.value?.map(item => item.path))
}
</script>
```

::note
Коллекции с `private: true`{lang="ts-type"} намеренно не попадают в дамп для браузера и запрашиваются через серверный маршрут, поэтому им нужен работающий сервер: полностью статическая выгрузка на такие запросы ответить не может.
::

## Типографика {#typography}

Bitrix24 UI содержит собственные реализации всех компонентов prose для бесшовной интеграции с `@nuxt/content`. Так оформление остаётся единообразным, типографика полностью под контролем, а контент сразу выглядит согласованно и соответствует дизайн-системе Bitrix24 UI.

::note{to="/docs/typography/"}
Вся система **типографики** и все доступные компоненты prose для выразительного и единообразного оформления контента — в разделе «Типографика».
::

## Утилиты {#utils}

Bitrix24 UI включает помощники, которые приводят данные из `@nuxt/content` к формату, ожидаемому его компонентами.

### `mapContentNavigation`

Утилита берёт навигацию из `queryCollectionNavigation` и рекурсивно преобразует её в массив объектов, которые подходят разным компонентам.

`mapContentNavigation(navigation, options?)`
- `navigation`: дерево навигации (массив ContentNavigationItem).
- `options` (необязательный):
  - `labelAttribute`: (string) какое поле использовать как подпись (по умолчанию `title`)
  - `deep`: (number или undefined) сколько уровней навигации включать (по умолчанию `undefined` — все уровни)

**Пример:** как показано ниже на примере хлебных крошек, утилиту обычно используют, чтобы привести данные навигации к нужному формату.

```vue [app.vue]
<script setup lang="ts">
import { mapContentNavigation } from '@bitrix24/b24ui-nuxt/utils/content'
import { findPageBreadcrumb } from '@nuxt/content/utils'

const { data: navigation } = await useAsyncData('navigation', () => queryCollectionNavigation('content'))

const breadcrumb = computed(() => mapContentNavigation(findPageBreadcrumb(navigation?.value, page.value?.path, { indexAsChild: true })).map(({ icon, ...link }) => link), { deep: 0 })
</script>

<template>
  <B24Page>
    <B24PageHeader v-bind="page">
      <template #headline>
        <B24Breadcrumb :items="breadcrumb" />
      </template>
    </B24PageHeader>
  </B24Page>
</template>
```

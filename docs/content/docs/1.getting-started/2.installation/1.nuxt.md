## Настройка {#setup}

### Шаблон для Nuxt {#use-a-nuxt-template}

Начните с одного из [официальных шаблонов](/templates/): кнопка `Use this template` на GitHub или командная строка:

::code-group

```bash [Dashboard]
git clone https://github.com/bitrix24/templates-dashboard.git <project-name>
cd <project-name>
pnpm install
pnpm run dev
```

```bash [Starter]
git clone https://github.com/bitrix24/starter-b24ui.git <project-name>
cd <project-name>
pnpm install
pnpm run dev
```

::

::note
Аргумент `<project-name>` — имя каталога, в котором будет создан проект. Замените его названием вашего проекта.
::

### Добавление в проект на Nuxt {#add-to-a-nuxt-project}

::steps{level="4"}

#### Установите пакет Bitrix24 UI {#install-the-bitrix24-ui-package}

::code-group{sync="pm"}

```bash [pnpm]
pnpm add @bxshefby/b24ui-nuxt @bitrix24/b24icons-vue tailwindcss
```

```bash [yarn]
yarn add @bxshefby/b24ui-nuxt @bitrix24/b24icons-vue tailwindcss
```

```bash [npm]
npm install @bxshefby/b24ui-nuxt @bitrix24/b24icons-vue tailwindcss
```

```bash [bun]
bun add @bxshefby/b24ui-nuxt @bitrix24/b24icons-vue tailwindcss
```

::

::note{to="/docs/getting-started/package/"}
Приложение на пакете из npm-организации `@bitrix24` переводится на `@bxshefby/b24ui-nuxt` псевдонимом в `package.json` или заменой имени.
::

#### Добавьте модуль Bitrix24 UI в `nuxt.config.ts`{lang="ts-type"} {#add-the-bitrix24-ui-module-in-your-nuxtconfigts}

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@bxshefby/b24ui-nuxt']
})
```

#### Подключите Tailwind CSS и Bitrix24 UI в CSS {#import-tailwind-css-and-bitrix24-ui-in-your-css}

::code-group

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@bxshefby/b24ui-nuxt";
```

```ts [nuxt.config.ts] {3}
export default defineNuxtConfig({
  modules: ['@bxshefby/b24ui-nuxt'],
  css: ['~/assets/css/main.css']
})
```

::

::tip
При использовании [`Nuxt Layers`](https://nuxt.com/docs/getting-started/layers) модуль сам создаёт директивы [`@source`](https://tailwindcss.com/docs/functions-and-directives#source-directive) для каталога каждого слоя, и Tailwind CSS ищет утилитарные классы во всех исходных файлах слоёв.
::

::callout{color="air-secondary"}
Рекомендуем поставить в VSCode расширение [Tailwind CSS IntelliSense](https://marketplace.visualstudio.com/items?itemName=bradlc.vscode-tailwindcss) и добавить такие настройки:

```json [.vscode/settings.json]
{
  "files.associations": {
    "*.css": "tailwindcss"
  },
  "editor.quickSuggestions": {
    "strings": "on"
  },
  "tailwindCSS.classAttributes": ["class", "b24ui"],
  "tailwindCSS.classFunctions": ["defineAppConfig"]
}
```

::

#### Оберните приложение в компонент App {#wrap-your-app-with-app-component}

```vue [app.vue]
<template>
  <B24App>
    <NuxtPage />
  </B24App>
</template>
```

::note{to="/docs/components/app/"}
Компонент `App` задаёт глобальные настройки. Без него не работают **Toast**, **Tooltip** и **программные оверлеи**.
::

::

## Опции {#options}

Bitrix24 UI настраивается опциями в `nuxt.config.ts`.

### `colorMode`

Опция `colorMode` включает или отключает интеграцию цветовой схемы из `@vueuse/core`.

- По умолчанию: `true`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@bxshefby/b24ui-nuxt'],
  css: ['~/assets/css/main.css'],
  b24ui: {
    colorMode: false
  }
})
```

### `theme.unstyled`

Опция `theme.unstyled` убирает из компонентов все классы темы по умолчанию. Остаются только их структура и классы, которые вы передаёте через `class`, `b24ui` или `app.config.b24ui`.

- По умолчанию: `false`{lang="ts-type"}

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@bxshefby/b24ui-nuxt'],
  css: ['~/assets/css/main.css'],
  b24ui: {
    theme: {
      unstyled: true
    }
  }
})
```

::warning
Вместе с оформлением убираются и **структурные** классы (позиционирование, переходы, flex/grid). У компонентов со сложной раскладкой, таких как `Modal`, `Drawer` или `Calendar`, раскладку придётся задать самостоятельно — как в unstyled-режиме PrimeVue.
::

### `theme.prefix`

Опция `theme.prefix` задаёт тот же префикс, что и в импорте Tailwind CSS. Так компоненты Bitrix24 UI используют правильные утилитарные классы и CSS-переменные с префиксом.

::code-group

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@bxshefby/b24ui-nuxt'],
  css: ['~/assets/css/main.css'],
  b24ui: {
    theme: {
      prefix: 'tw'
    }
  }
})
```

```css [app/assets/css/main.css] {1}
@import "tailwindcss" prefix(tw);
@import "@bxshefby/b24ui-nuxt";
```

::

Префикс автоматически добавляется ко всем утилитарным классам Tailwind и CSS-переменным в темах компонентов Bitrix24 UI:

```html
<!-- Без префикса -->
<button class="px-2 py-1 text-xs hover:bg-primary/75">Button</button>

<!-- С префиксом tw -->
<button class="tw:px-2 tw:py-1 tw:text-xs tw:hover:bg-primary/75">Button</button>
```

::note{to="https://tailwindcss.com/docs/styling-with-utility-classes#using-the-prefix-option" target="_blank"}
Подробнее о префиксе — в документации Tailwind CSS.
::

### `prose`

Опция `prose` принудительно подключает компоненты `<Prose>` из Bitrix24 UI, даже если `@nuxtjs/mdc` или `@nuxt/content` не установлены. Значение `false` отключает их, даже когда один из этих модулей установлен.

- По умолчанию: `true`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@bxshefby/b24ui-nuxt'],
  css: ['~/assets/css/main.css'],
  b24ui: {
    prose: false
  }
})
```

::note
Указывайте `prose: false` в ключе `b24ui` файла `nuxt.config.ts`, а не во встроенных опциях модуля: соответствие компонентов `@nuxtjs/mdc` читается только оттуда.
::

### `mdc` :badge{label="Устарело" color="warning" class="align-text-top"} {#mdc}

Вместо неё используйте опцию [`prose`](#prose).

### `content`

Опция `content` принудительно подключает компоненты `<Prose>` (если не задано [`prose: false`](#prose)) и `<B24Content>` из Bitrix24 UI, даже если `@nuxt/content` не установлен.

- По умолчанию: `false`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@bxshefby/b24ui-nuxt'],
  css: ['~/assets/css/main.css'],
  b24ui: {
    content: true
  }
})
```

::note{to="/docs/getting-started/integrations/content/#client-only-apps-spa"}
`@nuxt/content` поддерживается и в приложениях только для клиента (`ssr: false`{lang="ts-type"}), но для сборки нужен адаптер SQLite.
::

### `eslint` :badge{label="Soon" class="align-text-top"}

Опция `eslint` добавляет [конфигурацию ESLint](/docs/getting-started/integrations/eslint/nuxt/) Bitrix24 UI к той, которую генерирует [`@nuxt/eslint`](https://eslint.nuxt.com). Нужны оба: `@nuxt/eslint` и `eslint-plugin-better-tailwindcss`.

- По умолчанию: `false`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@nuxt/eslint', '@bxshefby/b24ui-nuxt'],
  css: ['~/assets/css/main.css'],
  b24ui: {
    eslint: true
  }
})
```

### `experimental.componentDetection`

Опция `experimental.componentDetection` включает автоматическое определение компонентов для tree-shaking. Исходный код сканируется, находятся реально используемые компоненты, и CSS генерируется только для них (вместе с их зависимостями).

В `nuxt dev` сканирование повторяется при сохранении файла `.vue`, `.ts`, `.mts`, `.js`, `.mjs`, `.cjs`, `.tsx` или `.jsx`, поэтому компонент, который использован впервые, получает стили без перезапуска сервера разработки.

- По умолчанию: `false`{lang="ts-type"}
- Тип: `boolean | string[]`{lang="ts-type"}

**Включить автоматическое определение:**

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@bxshefby/b24ui-nuxt'],
  css: ['~/assets/css/main.css'],
  b24ui: {
    experimental: {
      componentDetection: true
    }
  }
})
```

**Добавить компоненты для динамического использования:**

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@bxshefby/b24ui-nuxt'],
  css: ['~/assets/css/main.css'],
  b24ui: {
    experimental: {
      componentDetection: ['Modal', 'DropdownMenu', 'Popover']
    }
  }
})
```

::note
Если передать массив имён компонентов, автоматическое определение включается, а перечисленные компоненты (вместе с зависимостями) гарантированно попадают в сборку. Это удобно для динамических компонентов вроде `<component :is="..." />`, которые нельзя проанализировать статически.
::
